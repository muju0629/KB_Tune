# KB Tune 최종 구현·검증 기록

기준일: 2026-07-30

## 구현된 핵심

- 자연어 일정: `8월 5일 카페 갈래`에서 날짜·유형을 기기에서 구조화하고, 과거 카페 표본의 중앙값 20,000원을 제안한다.
- 지난 소비 열람: `이번 달 카페에 얼마 썼어?`에 기기가 보낸 날짜·유형·금액만으로 합계를 유도해 답한다. 제목은 보내지 않는다.
- 예측 데이터: 현금 결제는 제외하고 카드 거래·구조화된 일정 날짜·유형·금액만 사용한다.
- 미래 예측: 편향 보정 LightGBM 중앙값, q75 안전액, 일별 Hazard 발생확률·예상일을 기기에서 계산한다. 캘린더 Hazard는 검증 이득이 있었던 모임·데이트에만 사용한다.
- 추적성: Tune 상세와 사용자 승인·거절 감사 로그에 모델·피처 버전을 남긴다.
- 접지된 AI: 금액·확률은 결정론 엔진이 만들며, 외부 모델이 엔진에 없는 숫자를 만들면 응답 전체를 폐기하고 로컬 문장으로 대체한다.
- 실행형 대화: 일정 추가·금액 변경·다음 주 이동·소비 방향 변경·상품 화면 이동을 말풍선 안 버튼으로 실행한다.
- 가독성: 결론, 이유, 영향, 행동을 분리하고 금액·확률을 색과 굵기로 강조한다.

## 개인정보 경계

- 기본값은 `기기 안에서만`이며 외부 모델 호출이 없다.
- 이름·나이·질문 원문·일정 제목·금융 캡처 원본·OCR 원문은 서버와 외부 LLM에 보내지 않는다.
- 외부 AI를 직접 허용한 경우에만 금융 의도, 일정 날짜·유형·금액, 예산·카드 청구 등 답변에 필요한 집계값을 보낸다.
- iOS가 보내기 전 한 번, 백엔드가 외부 모델을 호출하기 전 다시 한 번 구조화한다.
- 음성은 온디바이스 인식만 사용하고, 지원하지 않는 기기에서는 키보드 입력으로 전환한다.
- 서버는 DB와 요청 본문을 저장하지 않는다. 제공자 보존 정책은 배포 시 계약·운영 설정으로 별도 확인해야 한다.

## 제출 시 남은 한계

- 실제 KB Pay 데이터 연동은 데모 범위이며 운영 연동으로 표현하면 안 된다.
- 현재 모델 성능은 합성 신규 홀드아웃 근거다. 실제 고객 성능이라고 과장하지 않는다.
- 누적 Bayesian 개인화는 신규 홀드아웃의 미질문 일반화를 통과하지 못해 사용자에게 노출하지 않는다.
- 실제 사용자 홀드아웃 MAE/MAPE와 과업 성공률 검증은 다음 단계다.
- 우승을 보장할 수는 없지만, 현재 강점은 “개인정보를 최소화하면서 일정 변화에 실제 금융 행동으로 반응하는 검증 가능한 AI”다.
