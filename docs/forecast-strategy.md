# 예측을 제품의 중심에 놓는다 — 무엇을 만들고 무엇을 멈추는가

작성 2026-07-30. 근거는 전부 이 리포 안의 측정값이다. 출처를 달지 못한 문장은 뺐다.

---

## 0. 결론 한 문장

> **메인 기능은 "다음 주에 얼마 나갈지, 항목별로, 틀릴 수 있는 폭까지"다.**

주간 화면의 큰 숫자(추가 사용 가능액)가 아니다. 그건 `남은예산 ÷ 남은주수` 산수라
누구나 만든다. 우리 것은 그 산수에 **들어가는 값**이다.

그리고 그 예보를 만드는 모델은 이미 있다. 붙어 있지 않을 뿐이다.

---

## 1. 측정이 이미 말한 것

### 1-1. 점 예측 정확도는 끝난 싸움이다

`tools/forecast_bench/results/results.md` — AI Hub 카드 승인매출 5,000명, 시간순 홀드아웃.

| | WAPE | R0 대비 |
|---|---:|---:|
| R0 개인 과거 평균 (현행 구조) | 0.137 | — |
| R6 LightGBM 허들 + 계층 shrinkage (최고) | 0.1297 | **+5.3%** |
| R8 Chronos-2 zero-shot | 0.1365 | +0.4% |

14종을 쌓아 올려서 5.3%다. 이유는 데이터에 있다 — **직전 달이 다음 달의 R²=0.958을
설명한다.** 어떤 모델도 "직전 달 복사"를 유의하게 이기지 못한다.

**이 방향으로 더 가면 안 된다.** 뱅크샐러드가 예측을 붙이겠다고 마음먹으면
`지난달 총액` 한 줄로 달성 가능 정확도의 95%를 가져간다. 정확도는 방어선이 아니다.

### 1-2. 대신 세 가지가 실제로 이겼다

| 성과 | 측정값 | 출처 |
|---|---|---|
| **구간 정직성** | 현행 방식 80% 구간이 실제로 65.7%만 덮었다 → CQR 80.1% | results.md |
| **습관 변화 감지** | 누적만 하는 모델 61주 → 이중 추정기 4주 | README 결론 |
| **확신의 수렴** | 26주간 카페 구간폭 −72%, 주간 총액 σ −38% | onboarding_sim.txt |

술 모임을 20주차에 끊었을 때 `quitSignal`이 7% → 41%(2주 후) → 93%(6주 후)로 올랐다.
금액 추정도 카페 8,000원(설치 직후 인구 통계) → 4,372원(실제 4,500원)으로 왔다.

### 1-3. 질문의 값어치는 정확도가 아니었다

`loop_sim.py` 4개 실험, 합성 300명 × 26주.

- 능동 학습(사용자 답변)의 예측 정밀도 개선: **+1.2%p.** 카드 명세가 정보의 ~85%를
  이미 갖고 있다
- 임계값이 압도적으로 중요하다: **0.60에서 정밀도 71%, 0.30에서 49.2%** — 22%p 차이
- 견고하다: 50% 무응답, 30% 부정확 답변에서도 성능 저하가 미미하다

**해석**: 질문은 정확도를 위한 도구가 아니다. **미래 의도**("다음 주 토요일에 약속
있어요")와 **부재의 귀속**("그만둔 건가 그냥 건너뛴 건가")을 얻는 도구다. 이력에
없는 정보이기 때문이다.

## 2. 뱅크샐러드가 구조적으로 못 하는 것

기능 차이가 아니라 **데이터 모델 차이**로 적는다. 기능은 따라잡히고 구조는 안 그렇다.

가계부는 **거래가 발생할 때 갱신되는 합계**다. 사용자에 대한 모델이 "일어난 일의 합"이다.
KB Tune은 **시간에 대한 기대를 가진 갱신 과정(renewal process)** 이다. 차이는 하나다 —

> **일어나지 않은 일이 정보가 된다.**

가계부는 발생한 거래만 본다. "6주마다 가던 미용실을 8주째 안 갔다"를 **표현할 문법이
없다.** 우리는 그게 `probabilityEnded`로 계산되는 값이다.

여기서 세 갈래가 나온다.

| | 가계부가 하는 말 | KB Tune이 할 수 있는 말 |
|---|---|---|
| 발생 전 | (없음) | "장보기 주기가 돌아왔어요 — 이번 주 78%" |
| 발생 후 | "생활비 35,000원" | "예상 35,000원에서 34,000원, 범위 안이에요" |
| **미발생** | (없음) | "와드 8주째예요. 그만두셨나요? 6주마다 40,000원이 돌아와요" |

세 번째 칸이 방어선이다. 그리고 여기가 **캘린더를 가진 쪽만 접근 가능한 칸**이다 —
일정은 데이터가 아니라 **움직일 수 있는 물건**이라서, 예보가 "다음 주로 옮기기"
버튼과 같은 화면에 있을 수 있다. 가계부의 예상 지출은 읽고 끝나는 숫자다.

## 3. 그래서 만들 것 — 붙이기 3, 새로 1

`SpendModel.swift`(476줄)는 파이썬 `mpp.py`에서 검증돼 이식됐다. 그런데:

```
SpendHistory.probability(of:within:)   호출부 0건   ← 죽어 있다
SpendHistory.quitSignal(for:)          호출부 0건   ← 죽어 있다
SpendModel.sampleTotal                 σ 계산에만
```

정작 화면의 "예상 소비" 카드는 `Models.swift:513 upcomingSpends` → `SpendHistory.upcoming`
이고, 그 안은 `lastDayOfYear + cadenceDays`와 `avgAmount`다. **결정론 산수다.**
확률도 구간도 없다. 그래서 장보기가 23일에는 뜨고 22일·24일에는 안 뜬다.

### ① 예상 소비 카드를 확률로 게이트한다

`upcoming(from:to:)`의 `next == 구간 내` 판정을 `probability(of:within:) ≥ 0.60`으로
바꾼다. 임계값 0.60은 `loop_sim.py`가 측정한 값이다(정밀도 71%). 확률순 정렬,
카드에 확률과 80% 구간 표시.

- 얻는 것: 규칙적인 패턴은 정확히, 불규칙한 패턴은 **안 뜬다.** 카페에 "갈 때 됐어요"가
  매일 뜨는 오작동이 구조적으로 막힌다(k=1이면 경과일이 정보를 주지 않는다)
- 비용: `upcoming` 내부 판정식 교체 + 카드에 필드 2개

### ② 종료 판정에 UI를 준다

`quitSignal ≥ 0.9`이면 하루 마감에 한 줄 띄운다. 답하면 그 패턴을 예보에서 뺀다.

**예산에서 자동으로 빼지 않는다** — `SpendModel.swift:251` 주석에 이미 적혀 있는 이유
그대로다. 한 주 안 갔다고 술값을 빼면 다음 주에 초과한다. 물어보는 트리거일 뿐이다.

- 얻는 것: 2절 세 번째 칸. **가계부가 낼 수 없는 문장.**
- 비용: 하루 마감 시트에 케이스 하나. 판정 로직은 이미 있다

### ③ 사후분포 구간을 예보 카드에 노출한다

`posteriorAmount`는 일정 추가 시트에서만 쓰인다. 예보 카드는 `avgAmount` 점추정이다.
같은 함수를 부른다.

### ④ 요일 항 — 유일하게 새로 쓸 것

`next_week.py`와 `methods.py`가 측정한 것: **질문이 두 종류다.**

```
요일 질문   "토요일에 약속 생기시나요?"      요일이 앵커인 습관
주간 질문   "이번 주 카페에 2만원 쓰실 듯"   요일을 모르는 습관
```

하나의 격자에 넣으면 한쪽이 죽는다 — 주 확률을 7로 나누면 최대 0.14라 임계값을
구조적으로 못 넘는다. 그리고 M3(분해 `P(주 발생) × P(요일|발생)`)가 좁은 질문
예산에서 M1(현행 요일 감쇠율)을 **부트스트랩 2,000회로 유의하게** 이겼다.

Swift 모델에 요일 항이 아예 없다. 추가할 것:

```
SpendCounters  + nByWeekday: [Double](7)         충분통계량 7개
SpendModel     w_d = (n_d + α·pop_d) / (N + α)   Dirichlet-multinomial, α = 4 (인구 4주 상당)
               집중도 = max(w) / Σw              ≥ 0.45 → 요일 질문 (next_week.py 값)
               P(요일 d) = P(주 발생) × w_d      = M3
```

30줄 안쪽이다. 이게 없으면 앱은 "이번 주 카페 2만원"밖에 못 말한다. **예측처럼
읽히는 문장은 요일 쪽이다.**

## 4. 그래서 멈출 것 — 각각을 죽인 숫자와 함께

| 멈춤 | 죽인 근거 |
|---|---|
| **Chronos-2 / TabPFN 증류** (spec §7) | R8이 R0 대비 **+0.4%**. 증류할 상한선이 존재하지 않는다. 단 조건이 불리했다(문맥 4점) — 이 전제는 6절 검증 ①이 다시 재고 그 전에는 재개하지 않는다 |
| **모델 계열 추가** | 사다리 14종이 5.3%를 냈다. Hawkes·상태공간·신경망을 더 올려도 R²=0.958이라는 벽은 그대로다 |
| **정확도 개선을 목표로 삼기** | 같은 벽. 목표를 구간 정직성·감지 지연·결정 품질로 옮긴다 |
| **정확도를 위한 능동 학습** | +1.2%p. 질문은 유지하되 목적을 의도·귀속으로 바꾼다 |
| **1.6억 건 전량 학습** | 5,000명 표본으로 이미 결론이 났다. 규모를 늘려도 R²=0.958이 안 바뀐다 |

## 5. 검증 공백 — 여기가 실제 위험이다

### ① 주지표가 평가된 적이 없다 ⚠️ 가장 큰 구멍

`forecast-bench-spec.md §1`이 T1(주간 총 지출)을 주지표로 못 박았다. 화면의 큰
숫자이기 때문이다. 그런데 AI Hub 데이터는 **월 집계 패널이라 주간 축을 복원할 수 없다**
(results.md 한계 2). `run_bench.py`는 월 축에서만 돌았다.

**앱이 보여주는 숫자는 한 번도 벤치마크된 적이 없다.** 보여주지 않는 숫자만 14종
비교했다.

`generate_synthetic.py`가 이미 일·주 단위 거래를 만든다. R-사다리를 `weekly`
패널에 다시 돌린다. 여기서 처음으로 **캘린더 일정을 known future covariate로 넣은
기여도**도 분리 측정된다 — AI Hub로는 불가능했던 것이고(spec §2-3), 우리 차별점의
핵심 가정이다.

### ② Swift ↔ Python 수치 대조가 없다

`SpendModel.swift:13`에 "수치가 갈리면 파이썬 자체검증을 기준으로 본다"고 적혀 있는데
**대조하는 테스트가 없다.** 같은 수식의 두 구현은 반드시 갈린다.

`mpp.py`에서 (counters, prior) → (mu, sd, p, quitSignal) 10쌍을 JSON으로 덤프하고
`KB_TuneTests`에서 assert한다. 한 파일, 한 테스트.

### ③ 달성 확률의 캘리브레이션이 없다

spec §5가 "사용자가 실제로 보는 숫자"라고 지목한 항목이다. results.md에 없다.

화면이 **81%라고 말할 때 실제로 81%가 지켜지는가.** 은행이 유일하게 신경 쓰는 숫자다.
합성 300명 × 26주로 신뢰도 다이어그램 한 장이면 된다. 지금 `RATE_CV = 1.0`은
`probability.py` 주석이 인정하듯 "사실상 모른다"의 표현이고, **캘리브레이션할 첫 번째 값**이다.

### ④ 콜드스타트 곡선이 없다

spec §6이 "이 그래프 한 장이 계층 구조를 정당화한다"고 쓴 것. 이력을
n ∈ {0, 2, 5, 20, 50}건으로 절단해 WAPE 꺾은선. 계층 사전분포 전체가 이 그래프에
걸려 있는데 아직 없다.

`onboarding_sim.txt`의 미용실이 왜 필요한지 보여준다 — 26주에 3건만 관측되어 주기
46.6일(실제 35일)·금액 41,333원(실제 28,000원)으로 틀렸지만 80% 구간
22,377~76,349원이 실제값을 덮었다. **점추정은 틀리고 구간은 정직하다.**

### 순서

```
① 주간 축 벤치마크    → 검증: 주간 WAPE·커버리지 표. 일정 공변량 기여도 분리
③ 확률 캘리브레이션   → 검증: reliability.png. 81%가 81%인가
④ 콜드스타트 곡선     → 검증: coldstart.png
② Swift 대조 테스트   → 검증: pytest·Swift 양쪽 통과 (구현과 병행)
```

①이 먼저다. 나머지 셋의 데이터 파이프라인이 여기서 나온다.

## 6. 발표와의 관계

`발표-구성안.md`는 차별점을 **"AI에게 무엇을 안 줄지 설계했다"**로 잡았다. 좋은
관통선이고 유지한다. 다만 지금 13장 어디에도 **예측 슬라이드가 없다.** 슬라이드 8은
기준 금액 데이터(콜드스타트 입력)이고 예측이 아니다.

두 이야기는 충돌하지 않는다. 오히려 **같은 이야기의 원인과 결과**다.

```
예측을 하려면 일정 제목을 봐야 한다
일정 제목은 민감정보다 (정형외과·성당)
→ 그래서 서버로 보낼 수 없다
→ 그래서 폰 안에서 도는 켤레 사후분포를 만들었다 (충분통계량 9개, 덧셈 몇 번)
→ 나가는 것 0건으로 예측이 된다
```

프라이버시는 **제약이 아니라 모델 선택의 이유**다. 그래서 온디바이스 베이지안을 골랐고,
그래서 26주 시뮬레이션으로 검증했고, 그래서 σ 하드코딩을 없앴다.

슬라이드 8과 9 사이에 예측 한 장을 넣는다. 넣을 수치는 정직한 것만 —
**"정확도는 5.3%밖에 못 올렸습니다. 대신 구간이 65.7%에서 80.1%가 됐고, 습관 변화를
61주에서 4주에 알아챕니다."** 정확도 자랑보다 이쪽이 금융 심사에서 세다.

## 7. 한계

- 위 측정 전부가 **합성 데이터** 기준이다. AI Hub도 합성이고 `generate_synthetic.py`는
  공표 통계에 앵커링된 생성물이다. 실사용자 홀드아웃은 없다
- 요일 항의 인구 프로파일(`pop_d`)은 실측 앵커가 없다. 카테고리별 발생 간격이 공개
  데이터에 존재하지 않는다(12개 zip 전수 조사) — `SpendPriors.cadence`의 `shape`가
  도메인 가정인 것과 같은 문제다
- 임계값 0.60은 합성 데이터에서 나온 값이다. 실사용자에서는 헛질문 비용이 다르게
  느껴질 수 있다
- 4절의 "멈춤"은 **월 축 결과에 근거한다.** 5절 ①이 주간 축에서 다른 그림을 보이면
  Chronos 재고는 다시 열린다
