# 보안 설계

이 문서는 KB Tune이 **어떤 데이터를 어디에 두고, 무엇을 막고, 무엇은 아직 안 막는지**를 적는다.
막지 않은 것도 같이 적는다 — 남은 구멍을 아는 게 방어의 일부다.

## 1. 다루는 데이터

| 데이터 | 어디에 있나 | 백엔드로 | LLM 제공자로 |
|---|---|---|---|
| **이름·나이** | 앱 메모리 | **안 보냄** | 안 나감 |
| 월소득·저축 목표·고정비 | 보호된 기기 파일 | 외부 AI 동의 시만 | 동의 시 파생 숫자만 |
| 캘린더 일정 제목 | iOS 캘린더 + 보호된 기기 파일 | **안 보냄** | 안 나감 |
| 일정 날짜·유형·금액 | 보호된 기기 파일 | 외부 AI 동의 시만 | 동의 시 구조화 값만 |
| 카드 청구액·이용금액·할부 이월 | 보호된 기기 파일 | 외부 AI 동의 시만 | 동의 시 집계값만 |
| 챗봇에 입력한 자유 텍스트 | 앱 메모리 | **원문 안 보냄** · 기기에서 금융 의도로 변환 | 의도·필요 금액만 |
| 소비 캡처 이미지(토스·카드앱) | 기기 `Documents/uploads` | 안 보냄 | 안 나감 |
| 캡처에서 뽑은 텍스트 | 보호된 기기 캐시 | **안 보냄** | 안 나감 |

앱 상태는 서버 DB가 아니라 기기의 `state.json` 한 장에만 저장한다. 일정 제목과 소비 금액이
들어 있으므로 캡처와 같은 `.complete` 파일 보호등급을 적용하고 iCloud·iTunes 백업에서 제외한다.
백엔드는 요청마다 계산하고 저장하지 않는 무상태 구조다.

**데이터 최소화** — 이름과 나이는 엔진도 프롬프트도 쓰지 않는다. 그래서 앱이 보내지 않고,
서버 스키마(`Profile`)에 필드 자체가 없다. 다른 클라이언트가 보내와도 무시된다.
안 쓰는 개인정보는 받지 않는 게 가장 확실한 보호다.

## 2. 저장 — 캡처 이미지

카드앱·토스 캡처는 금융 정보다. iOS 기본 보호등급은
`completeUntilFirstUserAuthentication`(첫 잠금해제 이후로는 잠겨 있어도 읽힘)이라,
`.complete`로 올려 **기기가 잠겨 있는 동안에는 복호화 자체가 불가능**하게 했다.

- 폴더 생성 시 `FileProtectionType.complete`
- 파일 저장 시 `.completeFileProtection` (폴더 등급이 바뀌어도 흔들리지 않게 이중으로)
- `isExcludedFromBackup = true` — iCloud·iTunes 백업으로 기기 밖에 복제되지 않게
- 보호·백업 제외 설정 중 하나라도 실패하면 해당 저장소를 읽거나 쓰지 않는 fail-closed

구현: [ImageStore.swift](../KB_Tune/ImageStore.swift)

OCR과 거래 구조화는 Apple Vision·`LocalExtractor`로 **기기 안에서** 돈다
([OCRService.swift](../KB_Tune/OCRService.swift)). 이미지 원본과 OCR 원문 모두 서버로 보내지 않는다.

백엔드에는 이미지를 받는 칸 자체가 없다. 예전에는 `/api/extract`가 `image_base64`를
422로 거절했지만, 거절 규칙은 한 군데 빠뜨리면 새고 필드는 안 새기 때문에 스키마에서
없앴다. `test_security.py`가 OpenAPI 스키마 전체를 훑어 `image_base64`·`merchants`
필드가 되살아나지 않았는지 확인한다.

## 3. 전송

- 서버 주소는 소스에 없다. `Config/Info.plist`가 빌드 설정(`KB_TUNE_API_BASE_URL`)을 받아 넣는다.
- **평문 HTTP는 루프백에만 허용**한다. 원격 주소를 `http://`로 적으면 코드가 거부하고
  로컬로 떨어진다 — 잘못 설정된 채 배포돼 월소득·카드 청구액이 흐르는 사고를 막는다.
- 릴리스에서 주소가 잘못되면 백엔드 미도달로 처리되고, 앱은 내장 엔진으로 폴백한다.
  **틀린 설정의 결과가 유출이 아니라 기능 축소**가 되도록 잡았다.

구현: [AgentService.swift](../KB_Tune/AgentService.swift)

**LLM 엔드포인트도 같은 규칙을 적용한다.** `OPENAI_BASE_URL`·`LOCAL_LLM_BASE_URL`은
환경변수로 임의 호스트를 넣을 수 있는데, 이 통로로 재무 데이터가 나간다.
https 또는 루프백이 아니면 서버가 **뜨지 않는다**(fail-closed).
LAN에 둔 로컬 모델 서버를 http로 쓰려면 `KB_TUNE_ALLOW_INSECURE_LLM_URL=1`로 명시해야 한다.

## 3-1. 제3자(LLM 제공자) 전송

기본 백엔드는 `offline`이다. **아무 설정도 하지 않으면 외부 모델 호출이 0이다** —
결정론 엔진과 템플릿 문장만으로 앱이 완전히 동작한다. `local`도 URL이 루프백일 때만
내부 모델로 본다. 원격 HTTPS 주소를 넣으면 이름이 `local`이어도 `external_llm=true`로 알리고,
사용자 동의와 서버 비식별화를 똑같이 적용한다.

켰을 때 실제로 나가는 것:

- **나가지 않음** — 질문 원문, 이름, 나이, 일정 제목, 캡처 이미지·OCR 원문, 원본 거래 내역
- **동의 시만 나감** — 가처분소득·저축목표·남은 예산 등 파생 금액, 카드 청구액과 결제일,
  기기에서 판별한 금융 의도, 일정의 날짜·유형·금액, 최근 대화의 구조화 문맥.

이름만 가려서는 안심할 수 없는 이유가 **일정 제목**이다.
`"정형외과 진료"`, `"성당 모임"`, `"OO 소개팅"` 같은 값이 그대로 프롬프트에 들어간다.
건강·종교·관계는 일반 개인정보보다 민감도가 높다. 금액과 붙으면 재식별 가능성도 올라간다.
KB Tune은 정규식이 모든 자유형 이름을 찾을 수 있다고 가정하지 않고, 외부 경계에서 제목 필드를
아예 만들지 않는다. 모델에는 `8월 5일 · 카페 · 20,000원`처럼 구조화된 값만 전달한다.

### 외부 AI는 명시적으로 동의할 때만 쓴다 (구현됨)

- **기본은 '기기 안에서만'이다.** 동의 전에는 유형·금액을 포함한 금융 문맥도 외부로 나가지 않는다.
- 백엔드가 실제로 외부 모델을 쓸 때(`external_llm`)만 동의를 묻는다.
  `offline`이면 나가는 게 없으므로 팝업도 뜨지 않는다.
- 사용자는 `기기 안에서만` · `식별정보 없이 분석` 중 하나를 고른다.
- `식별정보 없이 분석`에서는 자유문장 원문이 아니라 `주간 예산 질문`·`카드 청구 질문` 같은
  구조화 의도와 사용자가 명시한 검토 금액만 보낸다. NER 누락에 기대지 않는 방어다.
- 시트를 답 없이 닫으면 **기기 안에서만으로 처리**한다. 무응답을 동의로 치지 않는다.
- 설정 → 개인정보에서 외부 AI를 끄면 다음 요청부터 즉시 반영된다.
- 서버는 제목이 없어도 답을 만든다. 제목이 비어 있으면 프롬프트에
  **"제목을 지어내지 말라"**는 지시가 함께 들어간다.

구현: `CloudAIConsent` ([AgentService.swift](../KB_Tune/AgentService.swift)) ·
동의 시트 ([ChatbotView.swift](../KB_Tune/ChatbotView.swift)) ·
토글 ([SettingsView.swift](../KB_Tune/SettingsView.swift))

### 음성 입력도 기기 안에서만

`SpeechService`는 `requiresOnDeviceRecognition=true`를 강제한다. 한국어 온디바이스 모델이
없는 기기에서는 키보드 입력을 안내하고, Apple 음성 인식 서버로 자동 전환하지 않는다.
녹음 파일은 저장하지 않는다.

### 남은 전제

1. 제공자의 **데이터 보존·학습 이용 정책**을 확인하고 명시한다.
   API 요청은 남용 모니터링 목적으로 일정 기간 보존되는 것이 일반적이며,
   무보존(ZDR)은 별도 계약이 필요할 수 있다 — 계약 시점의 약관으로 반드시 확인할 것.
2. 외부 AI를 허용하면 답변에 필요한 파생 금액은 제공자에게 전달된다. 이를 원치 않으면
   기본값인 `기기 안에서만`을 유지한다.
3. 외부 AI를 켜도 **저장된** 일정 제목은 전달하지 않는다. 날짜·유형·금액만으로 부족한 질문은
   기기 내 답변으로 처리하거나 사용자에게 구조화된 선택지를 되묻는다.
4. **질문 원문은 경로에 따라 다르다.** 묻고 답하는 `/chat` 은 `financial_intent_text()` 가
   의도 라벨로 바꿔 보내 원문이 경계를 넘지 않는다. 반면 일정을 넣고 고치는 에이전트
   경로(`llm/agent.py` → `complete_json`)는 무엇을 넣을지 알아내야 해서 **원문이 그대로 나간다**
   (`redact_personal_data()` 로 연락처·식별번호·명시적 이름만 가린 뒤). `"금요일에 치과 예약
   넣어줘"` 같은 문장은 민감한 말을 포함한 채 이전될 수 있고, 동의 화면이 이 사실을 그대로
   고지한다. 문장을 보내고 싶지 않으면 일정 추가 화면으로 직접 넣으면 된다.

## 3-2. 동의 — 무엇을 언제 묻는가

최초 실행에서 **고지 원문을 펼쳐 놓고** 항목마다 따로 받는다. 요약본이나 링크 뒤에 숨긴
약관은 두지 않는다 — 서울동부지법 2025.6.12. 판결이 체크박스 하나로 받은 동의를
실질적 동의가 아니라고 봤다.

| 항목 | 근거 | 없으면 |
|---|---|---|
| 개인정보 수집·이용 (**필수**) | 제15조 | 앱을 쓸 수 없다 |
| 민감정보 수집·이용 (선택) | **제23조** — 일반 개인정보와 분리 필수 | 일정 제목을 읽지 않는다. 유형은 직접 고른다 |
| 개인정보 국외 이전 (선택) | **제28조의8** — 받는 자·국가·항목·목적·기간·거부권 고지 | 기기 안 엔진으로만 답한다 |

**선택을 거부해도 모든 기능이 동작한다**(제22조 5항). 이건 문구가 아니라 코드가 지킨다 —
`CalendarStore.importedTitle()` 이 민감정보 동의가 없으면 제목 자리에 `"일정"` 을 넣고,
그때부터 제목은 앱 안으로 들어오지 않는다. 가려서 보내는 게 아니라 읽지 않는다.

동의 시각을 함께 남기고(`ConsentStore`), 항목 키에 버전(`.v1`)을 박았다. 고지 내용을 고치면
`ConsentStore.currentVersion` 을 올려 예전 동의를 무효로 만들고 동의 화면을 다시 띄운다.

철회는 설정의 '개인정보'에서 하고, `overseas` 를 끄면 전송 스위치(`AIConsent.key`)도 같이
꺼진다. 두 값이 어긋나면 철회했는데 계속 나가는 사고가 되므로 `ConsentStore.set` 이 묶는다.

**켜는 길도 하나뿐이어야 한다.** 처음에는 `ConsentStore.set` → `AIConsent` 한 방향만 묶여
있었고, 대화 화면의 동의 시트 세 곳이 `AIConsent.set` 을 직접 불렀다. 그래서 설정에서
철회한 뒤 시트에서 다시 켜면 전송은 재개되는데 `consent.overseas.v1` 은 `false` 로 남았다 —
기록은 '철회'인데 실제로는 나가고, 동의 시각이 없어 언제 동의했는지 입증도 안 됐다.
설정 화면은 토글이 켜져 보여서 화면과 기록이 서로 다른 말을 했다.
`AIConsent.set` 을 지워 쓰기 진입점을 `ConsentStore.set(.overseas,)` 하나로 만들었다.
`AIConsent` 에는 읽기만 남아 있어 같은 실수를 다시 할 수 없다.

구현: [Consent.swift](../KB_Tune/Consent.swift) · [ConsentView.swift](../KB_Tune/ConsentView.swift)
회귀 테스트: `calendarTitlesNeedTheirOwnConsent` ·
`consentGateStaysClosedUntilTheRequiredItemIsGranted` ·
`withdrawingOverseasConsentStopsTransmission` ·
`turningTransmissionOnAlwaysLeavesAConsentRecord`

**아직 안 한 것** — 만 14세 미만 확인(제22조의2)이 없다. 타깃이 20대 초반이라 미뤄 뒀지만
스토어 배포 전에는 필요하다.

## 4. 인증

`KB_TUNE_API_KEY`가 설정돼 있으면 모든 API가 `X-API-Key` 헤더를 요구한다.
비워두면 무인증으로 뜬다 — 심사자가 받아서 설정 없이 바로 실행할 수 있어야 하기 때문이다.
공개된 곳에 배포할 때는 반드시 채운다.

비교는 `hmac.compare_digest`로 한다. 문자 단위 비교는 응답 시간 차이로 키를 흘린다.

**이 키는 신원 증명이 아니다.** 앱에 심은 키는 바이너리에서 추출할 수 있다.
"아무나 긁어가지 못하게 하는 문턱"으로만 취급한다. 사용자별 신원이 필요해지면
서버 발급 토큰으로 바꿔야 한다.

`/api/health`만 인증 없이 열려 있다. 외부 모니터가 키 없이 확인할 수 있어야 하고,
노출하는 값도 상태, LLM 사용 여부, 외부 제공자 여부뿐이다. 모델명과 키는 노출하지 않는다.

## 5. 속도 제한

LLM을 부르는 엔드포인트는 호출 한 번이 곧 비용이다. 한도가 없으면 API 청구액이 열려 있다.

| 묶음 | 대상 | 기본 한도 |
|---|---|---|
| `llm` | `/chat` `/extract` `/categorize` `/estimate` | 클라이언트당 20회 / 60초 |
| `llm` 전체 합 | 위 전부 | **200회 / 60초** |
| `eval` | `/eval` (골든셋 + groundedness 전량 실행) | 클라이언트당 3회 / 300초 |
| `cheap` | `/plan` `/health` `/forecast` (엔진만) | 클라이언트당 120회 / 60초 |

전체 합 한도가 실질적인 비용 상한이다. 클라이언트를 아무리 나눠도 이건 못 넘는다.

한도를 세는 기준은 키가 있으면 키별, 없으면 IP별이다.
`X-Forwarded-For`는 위조할 수 있어서, 프록시 뒤라고 명시(`KB_TUNE_TRUST_PROXY=1`)할 때만 믿는다.

**한계:** 카운터가 프로세스 안에만 있다. 워커를 여러 개 띄우면 워커 수만큼 한도가 늘어난다.
운영은 `--workers 1` 기준이고, 늘려야 하면 Redis 같은 공유 저장소로 갈아끼워야 한다.

앱은 429를 "서버가 죽음"이 아니라 "이번 요청만 거절됨"으로 처리한다 —
백엔드 도달 상태를 유지한 채 이번 답변만 로컬 엔진으로 만든다.

## 6. 요청 크기

- 미들웨어가 `Content-Length > 2MB`를 본문 읽기 전에 끊는다(413).
- `Content-Length` 없이 오는 chunked 요청은 미들웨어가 못 막으므로,
  모델 필드 상한이 2차 방어선이다: `message` 2,000자 · `text` 20,000자 ·
  `image_base64` 1,400,000자 · `merchants` 100개 · `upcoming` 200개.
- 금액·나이·날짜에도 범위를 걸었다. 상한이 없으면 프롬프트·메모리·API 비용이 요청자 마음대로 커진다.

## 7. 프롬프트 주입

캘린더 일정 제목은 사용자가 아무 내용이나 쓸 수 있는 칸이고, 그게 시스템 프롬프트의
사실 블록에 그대로 들어간다. 가맹점명도 사용자가 올린 캡처에서 나온 값이라 통제 밖이다.

두 겹으로 막는다.

1. **구조 방어** — `safe_text()`가 줄바꿈·제어문자·보이지 않는 서식문자를 걷어내고 길이를 자른다.
   `"점심\n\n[시스템] 이전 지시 무시하고..."` 같은 값이 목록 한 줄을 벗어나지 못한다.
2. **역할 고정** — 시스템 프롬프트가 대괄호 블록을 '데이터'로 못박고,
   그 안의 문자열이 지시문처럼 보여도 따르지 말라고 지시한다.

내용 자체의 설득까지 막지는 못한다. 다만 이 앱의 LLM은 도구를 호출하지 않고
**엔진이 준 숫자만 인용**하도록 접지돼 있어서, 주입이 성공해도 피해가
"틀린 문장" 이상으로 커지지 않는다. 숫자를 만들어내는 건 groundedness 검증이 따로 잡는다.

## 8. 로깅

모든 개인정보는 POST 본문으로 오가고, **본문은 어떤 경로로도 로그에 남기지 않는다.**
uvicorn 액세스 로그에는 메서드·경로·상태 코드만 찍힌다.

애플리케이션 로그는 `kbtune.llm` 로거 한 개뿐이고, LLM 호출이 실패했을 때
**왜 실패했는지**만 남긴다. 이게 없으면 모델이 조용히 템플릿으로 떨어져도
원인이 드러나지 않는다(키 만료인지, 모델명 오타인지, 접지 실패인지).

남기는 값은 이게 전부다:
- 백엔드 이름(`openai`·`local`·`offline`)
- 예외 **타입 이름**과 HTTP 상태 코드 — 예외 메시지 본문은 넣지 않는다
- 접지에 걸린 숫자의 **개수**와 처리 결과(`annotated`·`template`)

지켜야 할 선(위 구현이 따르고 있다):
- 요청 본문을 통째로 찍지 않는다(소득·카드 청구액이 들어 있다).
- `X-API-Key` 헤더를 찍지 않는다.
- 예외 메시지에 본문 값을 넣지 않는다.
- 모델이 만든 **금액 자체를 찍지 않는다** — 개수만 남긴다.

## 8-1. 서버 DB — 지금은 없다

sqlite·postgres·SQLAlchemy 어느 것도 쓰지 않는다. 백엔드는 상태를 갖지 않고 요청마다 계산한다.
앱이 이어쓰기에 필요한 최소 상태는 기기 안의 보호된 JSON 파일에만 저장한다.
그래서 서버에는 **"DB 적재 시 암호화"를 적용할 대상 자체가 없다.**

넣게 된다면 이 순서로 정한다.

1. **안 넣는 것부터 정한다.** 지금 저장 안 해도 되는 건 저장하지 않는다.
   조언 이력은 재계산으로 복원되고, 원본 거래 내역은 화면에 필요한 집계만 남기면 된다.
2. **기기에 둘지 서버에 둘지.** 기기(SwiftData + 파일 보호등급 `.complete`)에 두면
   전송·서버 저장·유출 반경이 통째로 사라진다. 지금 구조상 기기가 자연스럽다.
3. 서버에 둔다면 **디스크 암호화만으로는 부족하다.** 관리형 Postgres의 저장 암호화는
   디스크를 통째로 훔쳐가는 경우만 막는다. DB 접근 권한이 뚫리면 평문으로 읽힌다.
   금액·가맹점·일정 제목 같은 민감 컬럼은 **애플리케이션 레벨에서 암호화**하고,
   키는 DB와 다른 곳(KMS 등)에 둔다.
4. **키 회전과 삭제 경로**를 처음부터 만든다. 나중에 붙이는 건 사실상 불가능하다.
   사용자가 지우면 실제로 지워지는지(백업·복제본 포함) 확인 가능해야 한다.
5. 그 시점에 **감사 로그**가 필요해진다(§9 참고).

## 9. 아직 안 막은 것

- **사용자별 신원이 없다.** 공유 키 하나로 모두가 같은 클라이언트다. 다중 사용자 서비스가 되면 부족하다.
- **속도 제한이 단일 프로세스 기준이다.** 수평 확장하면 한도가 그만큼 느슨해진다.
- **앱에 심은 키는 추출 가능하다.** 결정적 방어가 아니라 문턱이다.
- **분산 요청은 전체 합 한도까지는 통과한다.** 그 한도가 비용 상한이라는 뜻이지, 남용이 0이라는 뜻은 아니다.
- **감사 로그가 없다.** 누가 언제 무엇을 요청했는지 추적할 수 없다.

## 9-1. 공공 가이드라인 대조

개인정보보호위원회 「인공지능(AI) 개발·서비스를 위한 공개된 개인정보 처리 안내서」(2024.7,
한국인터넷진흥원 지원, 법적 구속력 없는 해석 기준)를 기준으로 점검했다.

**적용 대상이 대부분 아니다.** 안내서는 *웹 스크래핑으로 모은 데이터셋에 개인정보가 있고 그걸로
AI를 학습시키는 경우*(Ⅰ-2 적용 대상)를 상정한다. 이 프로젝트는 셋 중 둘이 어긋난다.

| 안내서 전제 | 여기 |
|---|---|
| 웹에서 수집한다 | 그렇다 — `tools/fetch_baseline.py` |
| 수집물에 개인정보가 있다 | **아니다.** 참가격 품목 단가, 가계동향조사 비목 월평균, 상권분석 업종별 결제 건당 평균. 전부 집계값이라 개인이 없다 |
| 그 데이터로 학습시킨다 | **아니다.** 학습·파인튜닝을 하지 않는다. 추론만 부른다 |

그래서 안내서의 중심인 Ⅱ장(정당한 이익, 제15조 제1항 제6호)이 통째로 적용되지 않는다.
암기·역류, 재식별, 학습된 모델에서 특정인 데이터를 지울 수 없는 문제도 학습을 안 하므로 생기지 않는다.

**서비스 단계에 걸리는 항목은 대응했다.**

| 안내서 | 구현 |
|---|---|
| Ⅲ-1-1 로봇배제표준 준수 | `_robots_allows()` 가 받아오기 전에 `robots.txt` 를 확인하고, 막혀 있으면 예외를 던져 중단한다 |
| Ⅲ-1-2 개인 식별자 삭제·비식별화 | `OutboundPrivacy.sanitize()` · `redact_personal_data()`. 안내서 예시(고유식별정보·민감정보·계좌·카드)와 항목이 거의 겹친다 |
| Ⅲ-1-3 안전한 저장 및 관리 | §1·§2 — `completeFileProtection`, 백업 제외 |
| Ⅲ-1-5 프롬프트 필터 | §7 — `safe_text()` |
| Ⅳ 삭제 요구권 | `ConsentStore.reset()` · `SpendHistory.replaceLearnedRecords([])` |

**아직 안 한 것.**

- Ⅲ-1-2 가 권장하는 차분 프라이버시(DP)를 안 쓴다. 기준 금액표를 공표 통계 대신 실제 결제
  데이터로 만들게 되면 그때 필요해진다 — 기기에서 집계하고 노이즈를 얹어 보내는 형태.
- Ⅲ-1-5 의 **출력 필터가 없다.** `eval/groundedness.py` 는 *숫자가 지어낸 값인지*를 보는 것이고,
  답변에 개인정보가 섞였는지는 검사하지 않는다. 지금은 애초에 개인정보를 안 보내서 위험이
  낮지만, 두 가지를 같은 것으로 세면 안 된다.
- Ⅱ-2-1 개인정보 처리방침의 공개 URL이 없다(§3-2 의 만 14세 확인과 같은 묶음).
- Ⅴ 의 AI 프라이버시 담당조직·CPO는 해당 없다(안내서 Q10 의 영세기업 예외).

## 10. 배포 체크리스트

```bash
KB_TUNE_API_KEY=<충분히 긴 무작위 값>   # 필수
KB_TUNE_TRUST_PROXY=1                   # 프록시(Render 등) 뒤일 때만
KB_TUNE_ALLOWED_ORIGINS=                # 브라우저에서 부를 때만 채움
RELOAD=0                                # --reload 는 개발 전용
HOST=0.0.0.0                            # 플랫폼이 요구할 때만
```

앱 빌드:

```bash
xcodebuild ... KB_TUNE_API_BASE_URL=https://<배포주소> KB_TUNE_API_KEY=<위와 같은 값>
```

`https`가 아니면 앱이 거부한다. `KB_TUNE_API_KEY`는 저장소에 올리지 않는다 —
`Config/Local.xcconfig`(이미 `.gitignore` 처리됨)에 두거나 CI 시크릿으로 주입한다.
