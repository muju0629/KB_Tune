# KB Tune

**캘린더를 보고 이번 주에 쓸 수 있는 돈을 알려주는 소비 계획 에이전트예요.**
KB AI Challenge 출품작 · SwiftUI 네이티브 iOS 앱 + FastAPI 백엔드.

가계부는 이미 쓴 돈을 기록해요. KB Tune은 **아직 안 쓴 돈**을 다뤄요.
캘린더에 잡힌 약속과 과거 소비 패턴에서 앞으로 나갈 돈을 먼저 계산하고,
남는 금액을 알려드린 뒤, 계획이 흔들릴 것 같으면 무엇을 조정할지 제안해요.

> 앞부분은 **처음 써보시는 분을 위한 안내**예요.
> 알고리즘·스택·파일 구조는 [만드는 사람을 위한 문서](#만드는-사람을-위한-문서)부터 나와요.

---

# 처음 쓰는 분을 위한 안내

## 이 앱이 풀려는 문제

"이번 달 식비 30만원" 같은 카테고리 예산은 지키기 어려워요. 지금 눈앞의 약속이
그 예산에서 얼마를 가져가는지 알 수 없으니까요.

KB Tune은 **캘린더의 약속 하나하나에 금액을 붙여요.** 그래서 예산이
"식비 30만원"이 아니라 "이번 주 확정 지출 40,000원, 남은 60,000원"처럼
행동에 붙은 숫자가 돼요.

세 가지를 지켜요.

**1. 이유 없이 숫자를 줄이지 않아요.**
금액을 채울 때는 항상 근거를 같이 보여드려요.

> 성제님의 와드 주기는 6주 정도였어요.
> 5월 16일 42,000원 · 6월 27일 38,000원

**2. 줄이라고 말하지 않아요.**
"나한테 더 필요한 소비"로 고르신 항목(데이트·가족·모임)은 예산을 조정할 때
조정안에서 아예 빼요. 아낄 곳은 그 바깥에서 찾아요.

**3. 상품을 먼저 권하지 않아요.**
카드·적금은 계획을 다 세운 뒤에야 나와요. 그것도 현금흐름이 목표를
감당하는지 먼저 확인해 드린 다음이에요.

---

## 처음 켜면

**1단계 · 온보딩**
캘린더 연결 → 월 수입·저축 목표 → 좋아하는 것 → 소비 방향, 네 단계를 거쳐요.
좋아하는 것으로 고르신 항목(데이트·가족·모임 등)이 나중에 "건드리지 않을 소비"가 돼요.

**2단계 · 주간 화면에서 이번 주 쓸 수 있는 돈 보기**
앱을 열면 계산 과정이 아니라 결론이 먼저 나와요. 고정비·저축 목표·확정 일정을
모두 빼고 남은 금액이에요.

**3단계 · 일정을 넣어보기**
일정 제목만 적어도 과거 이력에서 금액을 찾아 채워드려요. 확정하기 전에
"이걸 넣으면 이번 주 사용 가능액과 목표 확률이 어떻게 되는지"를 먼저 보여드려요.

**4단계 · 하루가 끝나면 확인하기**
확인할 게 있는 날에만 카드가 떠요. 여기서 누르신 답이 다음 예측을 정확하게 만들어요.

**5단계 · 분석에서 어디에 쓰는지 보기**
필수 지출과 기타 지출로 나눠서, 이미 쓴 돈과 앞으로 나갈 돈을 색으로 구분해 보여드려요.

---

## 화면 넷

| 탭 | 하는 일 |
|---|---|
| **주간** | 이번 주 쓸 수 있는 금액 · 일정별 예상 지출 · 하루 마감 확인 · 예상 소비 제안 · 위험 일정 조정 · 월간 캘린더 |
| **대화** | 계획에 대해 묻고 답하기. 일정을 말하면 예상 금액과 남는 돈을 같이 계산해 드려요 |
| **분석** | 한 달 지출을 필수 / 기타로 나눠 보기 · 지출 완료·예상을 색으로 구분 · 결제 캡처 업로드 |
| **카드·적금** | 수입 − 고정비 − 일정비로 여유를 먼저 확인한 뒤 상품 비교 |

설정은 주간 화면 우상단 프로필 아이콘에 있어요. 하단 탭은 좌우로 밀어서도 넘길 수 있고,
주간 탭 안쪽(타임테이블·월간)에 들어가 계실 때 **주간을 한 번 더 누르면** 주간 메인으로 돌아와요.

---

## 돈의 세 가지 상태

돈을 한 덩어리로 보여드리면 "이 숫자가 이미 나간 돈인지, 나갈 돈인지"를 알 수 없어요.
KB Tune은 셋으로 갈라서 화면에 다르게 표시해요.

| 상태 | 뜻 | 화면에서 |
|---|---|---|
| **확정 지출** | 이미 결제했거나 반드시 나갈 돈 | 표시 없음(기본) · 분석에서 **노란색** |
| **예약 예산** | 일정에 배정했지만 아직 결제 전 | 🕐 **예약** 배지 |
| **패턴 예상** | 캘린더엔 없지만 주기가 돌아온 지출 | "이런 소비가 예상돼요" 카드 · 분석에서 **짙은 회색** |

**예약은 실제 출금이 아니에요.** 계좌에서 돈이 빠져나가지 않고, 쓸 수 있는 금액에서만 빠져요.
그래서 문구도 그렇게 써요.

> 8월 2일 데이트 비용으로 100,000원을 8월 계획 예산에 예약할까요? 실제 출금은 없어요.

---

## 하루 마감 — 앱이 물어보는 것

예측만 하고 맞았는지 확인하지 않으면, 앱이 배울 정답이 생기지 않아요.
하루 마감은 **확인할 게 있는 날에만** 떠요. 매일 알리지 않아요.

KB Pay가 연결되면 카드로 결제하신 지출은 앱이 이미 알아요. 그래서 이미 아는 걸 묻지 않고,
**예정돼 있었는데 카드 기록이 없는 지출**만 남겨서 여쭤봐요.

```
결제 기록이 없는 지출이 있어요
'와드'에 40,000원 쓸 예정이었는데 카드 결제 기록이 없어요. 현금으로 결제하셨나요?
[현금으로 결제했어요]  [아직 안 썼어요]
```

"현금으로 결제했어요"를 누르시면 예약이 확정으로 바뀌고, 그 답이 다음 예측의 근거가 돼요.

---

## 예상 소비 — 캘린더에 없는 지출

캘린더에 적지 않았지만 주기적으로 나가는 돈이 있어요. 과거 이력에서 주기를 찾아 미리 알려드려요.

```
7/23  쿠팡 장보기  예상 35,000원
      성제님의 쿠팡 장보기 주기는 10일 정도였어요.
      6월 23일 34,000원 · 7월 3일 36,000원 · 7월 13일 35,000원
      [계획에 넣기]  [이번엔 안 써요]
```

**이 금액은 예산에서 미리 빼지 않아요.** "계획에 넣기"를 누르셔야 반영돼요.
이유를 모른 채 남은 돈이 줄어드는 일이 없어야 하니까요.

---

## 자주 헷갈리는 것

**예약하면 돈이 빠져나가나요?**
아니에요. 실제 계좌는 그대로예요. "쓸 수 있는 금액" 계산에서만 빠져요.

**예상 소비는 왜 남은 돈에서 안 빠지나요?**
확정이 아니기 때문이에요. "계획에 넣기"를 눌러 동의하셔야 예산에 들어가요.

**일정을 취소하면 돈이 돌아오나요?**
지금 버전은 "다음 주로 옮기기"로 이번 주 부담을 덜 수 있어요.
취소했을 때 환불 확정분만 회수하는 기능은 다음 회차 과제예요.

**"예상"이 붙은 금액과 안 붙은 금액은 뭐가 다른가요?**
확인된 금액에는 "예상"을 붙이지 않아요. 추정치일 때만 붙여요.

# 만드는 사람을 위한 문서

## 핵심 루프

```
일정 추가 → 과거 이력·규칙으로 금액 추정 → 영향 표시(사용 가능액·목표 확률 전/후)
   → 위험하면 조정안 제시 → 확정 → 캘린더·예산·확률에 즉시 반영
   → 하루 마감에서 실제 결과 확인 → 다음 예측에 반영
```

숫자가 실제로 움직여요. 일정을 추가하면 히어로 금액이 내려가고, 예산을 넘기면 그 일정에
경고가 붙어요. 위험 카드에서 "다음 주로 옮기기"를 누르면 일정이 실제로 이동하고
이번 주 사용 가능액이 회복돼요.

---

## 알고리즘

### 안전 사용 가능액 — `BudgetEngine.weeklyAvailable`

```
가처분     = 월 수입 − 고정비 − 저축 목표
남은 예산   = 가처분 − 이번 달 지금까지 쓴 일정비
주간 가능액 = max(0, 남은 예산 ÷ 남은 주 수 × 방향계수 − 이번 주 확정 지출)
```

`남은 주 수`는 `ceil((월 일수 − 오늘 + 1) / 7)`로 구해요. 방향계수는 사용자가 고른 소비 방향에서 와요.

| 방향 | 주간 계수 | 일정 밖 소액 계수 |
|---|---|---|
| 줄이기 | 0.86 | 0.60 |
| 유지 | 1.00 | 1.00 |
| 늘리기 | 1.18 | 1.35 |

### 목표 달성 확률 — `BudgetEngine.probability`

몬테카를로 대신 **정규근사**를 써요(백엔드 시뮬레이션과 ±1%p 이내로 맞아요).

```
평균(μ)  = 남은 확정 일정 + 일정 밖 소액(7,500원/일 × 남은 일수 × 방향계수)
z        = (남은 예산 − μ) / σ          σ = 100,000
확률      = Φ(z)                        Φ = 표준정규 누적분포
```

### 반복 소비 패턴 탐지 — `SpendHistory`

같은 제목이 과거에 2건 이상이면 패턴으로 봐요. 평균 주기·주기 편차·평균 금액을 구하고,
**규칙성**을 다음처럼 0~1로 환산해요.

```
규칙성 = clamp(1 − (주기 편차 ÷ 평균 주기) ÷ 0.5,  0,  1)
```

편차가 주기의 20% 이내면 높게 잡혀요. 규칙적일수록 금액보다 **주기**를 근거로 내세워요.

```
와드          42일 (6주)   40,000원   규칙성 1.00
쿠팡 장보기     10일        35,000원   규칙성 0.93
주말 데이트     14일 (2주)   70,000원   규칙성 1.00
미용실         49일 (7주)   26,000원   규칙성 1.00
```

### 일정 태깅

일정 하나에 **결제 업종**(무엇에 썼나)과 **생활 목적**(왜 썼나)을 함께 붙여요.
스타벅스 결제 하나만으로는 데이트인지 공부인지 알 수 없기 때문이에요.
분석 화면은 이 둘을 합쳐 필수/기타로 묶어요.

## 설계 원칙

**숫자는 코드가, 문장은 LLM이.**
사용 가능액·달성 확률·혜택 계산은 전부 결정론 엔진(`BudgetEngine`, `RecoEngine`,
`SpendHistory`)이 담당해요. LLM은 계산 결과를 설명할 뿐 숫자를 만들지 않아요.
백엔드 `app/eval/groundedness.py`가 LLM 응답에 엔진이 내지 않은 숫자가 섞이면 잡아내요.

**앱은 백엔드 없이도 돌아가요.**
`BudgetEngine`은 백엔드 `app/engine`의 Swift 포트예요. 서버가 없거나 API 키가 없어도
같은 숫자가 나와요. 백엔드는 개인화 정확도와 자연스러운 문장을 더할 뿐이에요.

**단정하지 않아요.**
신용카드는 "발급 가능"이라 말하지 않고 심사 대상임을 밝혀요. 신청기간이 끝난 상품에
"가입 가능"을 표시하지 않아요. 실적을 채우려고 소비를 늘리라고 권하지 않아요.
추정치와 확인된 금액을 화면에서 구분해요.

## 기술 스택

| 영역 | 사용 기술 |
|---|---|
| iOS 앱 | Swift · SwiftUI (iOS 26.5) · EventKit(캘린더) · Vision(기기 내 OCR) · PhotosUI |
| 백엔드 | Python · FastAPI · Uvicorn · httpx |
| LLM | Anthropic Claude (설명·대화·비전 OCR). 오프라인·로컬 모델로 전환 가능 |
| 테스트 | pytest(백엔드 엔진 회귀 + AI 기능) · XCTest |

LLM 백엔드는 `LLM_BACKEND` 값으로 `offline`(템플릿, 비용 0) · `local`(OpenAI 호환 로컬 모델) ·
`claude` 중에 골라요. 무엇을 고르든 실패하면 템플릿으로 대체돼요.
