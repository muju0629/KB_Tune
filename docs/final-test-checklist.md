기준 커밋: `develop` HEAD (2026-07-29 `be29d60`)
대상: Cloud Run `kb-tune` (asia-northeast3) + iOS 앱

이 문서는 **오늘 바뀐 것 중심**이다. 전 기능 회귀가 아니라, 바뀌었기 때문에 깨질 수 있는
곳과 깨져도 티가 안 나는 곳을 먼저 본다. 각 항목의 "기대"와 다르면 "다르면 볼 곳"으로 간다.

## 1. 대화 — 오늘 모델이 바뀐 곳

**여기가 조용히 깨지는 자리다.** 모델 호출이 실패해도 앱은 오류를 안 띄우고 템플릿 문장으로
답한다. 사용자 눈에는 "답이 좀 딱딱하네" 정도로만 보인다.

| # | 할 일 | 기대 | 다르면 볼 곳 |
|---|---|---|---|
| 1-1 | 대화 탭 → "이번 주에 얼마까지 쓸 수 있어?" | 62,000원이 답에 나옴. 문장이 자연스러움 | 아래 판별법 |
| 1-2 | "적금 목표 지킬 수 있어?" | 확률 **81%** 언급 | 숫자가 다르면 엔진/프롬프트 불일치 |
| 1-3 | "다음 달에 뭐 살까 고민이야" 같은 **자유 질문** | 템플릿 티가 안 나는 답 | 템플릿이면 LLM 미도달 |
| 1-4 | 화면 숫자와 대화 숫자 대조 (주간계획 탭 사용가능액 ↔ 대화 답변) | **일치** | `makeChatRequestBody`의 `app_numbers` |

**템플릿 강등 판별법** — 아래 문장이 그대로 나오면 모델이 아니라 템플릿이다.
- `"이번 주에는 약 …원까지 쓸 수 있어요. 이번 달 일정 예상액은 …원으로 예상해요. 확인하고 싶은 일정을 말해 주세요."`
- 판별이 애매하면 같은 질문을 두 번 던져 본다. **글자까지 똑같으면 템플릿**, 조금이라도 다르면 모델이다.

## 2. 에이전트 — 실패가 화면에 그대로 뜨는 곳

대화와 달리 폴백이 곱지 않다. JSON 파싱이 실패하면 **"지금은 답을 만들지 못했어요.
다시 한번 말씀해 주시겠어요?"** 가 그대로 나온다.

| # | 할 일 | 기대 |
|---|---|---|
| 2-1 | "금요일에 치과 예약 넣어줘" | 일정 추가 **버튼**이 붙은 답변 |
| 2-2 | 그 버튼 누르기 | 캘린더에 실제로 들어감 |
| 2-3 | "그거 다음 주로 미뤄줘" | 번호로 지목해 이동 제안 |
| 2-4 | "방금 넣은 거 지워줘" | 삭제 제안 → 실행 |
| 2-5 | **2-1~2-4를 연달아 5회** | "답을 만들지 못했어요"가 **0회** |

> 2-5가 이번 모델 교체의 실질 검증이다. 1회 성공은 배관 확인일 뿐이고, 실제 프롬프트
> (일정 목록 + 대화 이력 전량)에서의 적중률은 반복해야 보인다. 1회라도 나오면 기록해 둘 것.

## 4. 개인정보 — 오늘 동의 구조를 건드림

`AIConsent`가 `ConsentStore(.overseas)`와 **같은 칸**을 읽도록 바뀌었다(`72a16d8`).
전에는 값이 둘이라 어긋날 수 있었다.

| # | 할 일 | 기대 |
|---|---|---|
| 4-1 | 설정에서 AI 스위치 끔 → 대화 탭 배지 확인 | `기기 안에서만` |
| 4-2 | 스위치 켬 → 배지 확인 | **바뀜** (3일째 이월된 버그 — 오늘 변경으로 해소됐는지가 관건) |
| 4-3 | 앱 종료 후 재실행 → 배지 | 켠 상태 유지 |
| 4-4 | 설정 → 개인정보 → 동의 3종(필수·민감·국외) 각각 눌러 보기 | 원문이 뜨고 개별 토글됨 |

> 4-2가 오늘 변경의 직접 검증이다. **여기가 여전히 안 바뀌면 원인은 두 값 불일치가 아니라

## 실패했을 때 빠른 분류

| 증상 | 1순위 원인 |

| 401 | `KB_TUNE_API_KEY` 앱↔서버 불일치 |
