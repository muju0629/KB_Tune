# KB Tune

**캘린더를 보고 이번 주에 쓸 수 있는 돈을 알려주는 소비 계획 에이전트.**
KB AI Challenge 출품작 · SwiftUI 네이티브 iOS 앱 + FastAPI 백엔드.

가계부는 이미 쓴 돈을 기록한다. KB Tune은 **아직 안 쓴 돈**을 다룬다.
캘린더에 잡힌 약속과 과거 소비 패턴에서 앞으로 나갈 돈을 먼저 계산하고,
남는 금액을 알려준 뒤, 계획이 흔들릴 것 같으면 무엇을 조정할지 제안한다.

---

## 핵심 아이디어 셋

**1. 일정이 곧 예산이다**
"이번 달 식비 30만원" 같은 카테고리 예산은 지키기 어렵다. 대신 캘린더의 실제 약속
하나하나에 예상 금액을 붙여서 "이번 주 확정 지출 40,000원 → 남은 62,000원"처럼
행동에 붙은 숫자로 만든다.

**2. 과거 이력으로 금액을 예측하고, 이유를 말한다**
일정 제목만 넣어도 과거에 같은 일정을 얼마씩·얼마 만에 썼는지 찾아 금액을 채운다.
중요한 건 금액이 아니라 **근거**다.

> 성제님의 와드 주기는 6주 정도였어요.
> 5월 16일 42,000원 · 6월 27일 38,000원

**3. 줄이라고 말하지 않는다**
"나한테 더 필요한 소비"(데이트·가족·모임)로 고른 항목은 예산을 조정할 때
조정안에서 제외한다. 아낄 곳은 그 바깥에서 찾는다.

## 화면

| 탭 | 하는 일 |
|---|---|
| **주간** | 이번 주 쓸 수 있는 금액 · 일정별 예상 지출 · **하루 마감 확인** · **예상 소비 제안** · 위험 일정 조정 · 월간 캘린더 |
| **대화** | 계획에 대해 묻고 답하기 (백엔드 Claude 스트리밍, 없으면 로컬 폴백) |
| **분석** | 7월 지출을 **필수 / 기타**로 나눠 보기 · 지출 완료·예상을 색으로 구분 · 결제 캡처 업로드 |
| **카드·적금** | 수입 − 고정비 − 일정비로 여유를 먼저 확인한 뒤 상품 비교 |

상품은 맨 오른쪽 탭에 있지만 **먼저 권하지 않는다.** 주간 화면 하단과 분석 화면 맨 아래에서
낮은 강조로만 진입 동선을 두고, 탭에 들어가도 현금흐름을 먼저 보여준 다음 상품을 제안한다.
설정은 주간 화면 우상단 프로필 아이콘.

## 핵심 루프

```
일정 추가 → 과거 이력·규칙으로 금액 추정 → 영향 표시(사용 가능액·목표 확률 전/후)
   → 위험하면 조정안 제시 → 확정 → 캘린더·예산·확률에 즉시 반영
```

숫자가 실제로 움직인다. 일정을 추가하면 히어로 금액이 내려가고, 예산을 넘기면 그 일정에
경고가 붙는다. 위험 카드에서 "다음 주로 옮기기"를 누르면 일정이 실제로 이동하고
이번 주 사용 가능액이 회복된다.

## 금액의 세 가지 상태

돈을 한 덩어리로 보여주면 "이 숫자가 이미 나간 돈인지 나갈 돈인지"를 알 수 없다.
`SpendState`로 셋을 갈라 화면에서 다르게 표기한다.

| 상태 | 뜻 | 계산 |
|---|---|---|
| **확정 지출** | 이미 결제했거나 반드시 납부 | 가용금액에서 전액 차감 |
| **예약 예산** | 일정에 배정했지만 아직 결제 전 | 가용금액에서만 제외 — **실제 출금 없음** |
| **패턴 예상** | 캘린더엔 없지만 주기가 돌아옴 | 예산에서 빼지 않고 카드로만 제안 |

예약은 "돈을 빼둔다"가 아니라 **가상 예약**이다. 그래서 문구도 그렇게 쓴다.

> 8월 2일 데이트 비용으로 100,000원을 8월 계획 예산에 예약할까요? 실제 출금은 없어요.

일정마다 **결제 업종**(무엇에 썼나)과 **생활 목적**(왜 썼나)을 함께 붙인다.
스타벅스 결제 하나로는 데이트인지 공부인지 알 수 없기 때문이다.

---

## 하루 마감

예측만 하고 맞았는지 확인하지 않으면 학습할 정답이 생기지 않는다.
하루 마감은 **확인할 게 있는 날에만** 뜬다. 매일 알리지 않는다.

KB Pay가 붙으면 카드로 결제된 지출은 앱이 이미 안다. 그래서 물어볼 필요가 없는 걸 묻지 않고,
**예정돼 있었는데 카드 기록이 없는 지출**만 남겨 되묻는다.

```
결제 기록이 없는 지출이 있어요
'와드'에 40,000원 쓸 예정이었는데 카드 결제 기록이 없어요. 현금으로 결제하셨나요?
[현금으로 결제했어요]  [아직 안 썼어요]
```

"현금으로 결제했어요"를 누르면 예약 예산이 확정 지출로 바뀌고, 그 결과가 다음 예측의
정답 데이터가 된다.

## 예상 소비 예측

`SpendHistory.swift` — 과거 지출에서 같은 제목이 2건 이상이면 패턴으로 본다.
평균 주기·편차·평균 금액을 계산하고, 주기가 규칙적일수록(편차 ÷ 주기가 작을수록)
금액 대신 **주기**를 근거로 내세운다.

```
와드          42일 (6주)   40,000원   규칙성 1.00
쿠팡 장보기     10일        35,000원   규칙성 0.93
주말 데이트     14일 (2주)   70,000원   규칙성 1.00
미용실         49일 (7주)   26,000원   규칙성 1.00
```

**캘린더에 없는데 주기가 돌아온 지출**은 주간 화면에 "이런 소비가 예상돼요" 카드로 뜬다.

```
7/23  쿠팡 장보기  예상 35,000원
      성제님의 쿠팡 장보기 주기는 10일 정도였어요.
      6월 23일 34,000원 · 7월 3일 36,000원 · 7월 13일 35,000원
      [계획에 넣기]  [이번엔 안 써요]
```

예측은 **확정이 아니므로 예산에서 미리 빼지 않는다.** "계획에 넣기"를 눌러야 반영된다.
사용자가 이유를 모르는 채로 숫자가 줄어드는 일이 없어야 하기 때문이다.

## 설계 원칙

**숫자는 코드가, 문장은 LLM이.**
사용 가능액·달성 확률·혜택 계산은 전부 결정론 엔진(`BudgetEngine`, `RecoEngine`,
`SpendHistory`)이 담당한다. LLM은 계산 결과를 설명할 뿐 숫자를 만들지 않는다.
백엔드 `app/eval/groundedness.py`가 LLM 응답에 엔진이 내지 않은 숫자가 섞이면 잡아낸다.

**앱은 백엔드 없이도 돈다.**
`BudgetEngine`은 백엔드 `app/engine`의 Swift 포트다. 서버가 없거나 API 키가 없어도
같은 숫자가 나온다. 백엔드는 개인화 정확도와 자연스러운 문장을 더할 뿐이다.

**단정하지 않는다.**
신용카드는 "발급 가능"이라 말하지 않고 심사 대상임을 밝힌다. 신청기간이 끝난 상품에
"가입 가능"을 표시하지 않는다. 실적을 채우려고 소비를 늘리라고 권하지 않는다.
추정치와 확인된 금액을 화면에서 구분한다(확인값엔 "예상"을 붙이지 않는다).

## 실행

**iOS**
```bash
open KB_Tune.xcodeproj      # Xcode 26.6+, iOS 26.5 시뮬레이터
```
`KB_Tune/` 폴더는 file-system-synchronized group이라 `.swift` 파일을 넣으면
프로젝트 수정 없이 빌드에 자동 포함된다.

**백엔드** (선택)
```bash
cd backend
pip install -r requirements.txt
cp .env.example .env         # ANTHROPIC_API_KEY (없으면 규칙 기반으로만 동작)
uvicorn app.main:app --reload
```

**테스트**
```bash
cd backend && pytest -q      # 엔진 회귀 + AI 기능 (20개)
# iOS: Xcode에서 ⌘U
```

## 데모 데이터

2026년 7월 캘린더 기반. 금액은 **본인 확인값**과 **데모 가정**이 섞여 있고, 앱 안에서도
구분해 표시한다.

| 구분 | 값 |
|---|---|
| 확인값 — 월 고정비 | 435,000원 (통신 7.5 · 교통 15 · 유류 6 · 구독 3 · 청약 10 · 보험 2만) |
| 확인값 — 단건 | 정장 15만 · 결혼식 7만 · 데이트 10만 · 제모 5만 · 와드 4만 |
| 확인값 — 출근 | **0원** (점심 무비용, 교통·유류는 고정비에 포함) |
| 가정 | 월 수입 220만 · 저축 목표 80만 · 일정 밖 소액 7,500원/일 |

파생 결과: 7월 일정비 801,000원 · 이번 주 사용 가능액 62,000원(화면에는 만원 단위로 반올림해
60,000원) · 목표 달성 확률 81%.

> 금액을 바꿀 때는 **iOS `BudgetEngine`·백엔드 `app/data.py`·양쪽 테스트를 함께** 고쳐야 한다.
> 세 곳이 같은 숫자를 보도록 테스트가 잠가 두었다.

**분석 탭 숫자는 별도다.** `AnalysisView`의 필수/기타 카테고리 금액은 캘린더 이벤트 합계가 아니라
페르소나의 실제 한 달 지출을 손으로 정리한 값이다(합계 약 1,602,000원). 캘린더 기반 일정비
801,000원과 일부러 따로 움직이므로 **두 숫자가 다른 것은 버그가 아니다.**
