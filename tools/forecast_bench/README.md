# forecast_bench — 소비 예측 모델 벤치마크

KB Tune 의 금액 추정을 "규칙 + 과거 평균"에서 검증된 예측 모델로 올리는 작업.
**목표는 가장 정확한 모델을 찾는 것이 아니라, 온디바이스에서 돌릴 수 있는 최선을
찾고 그것이 현재 방식보다 나은지 숫자로 증명하는 것**이다. 지면 그대로 보고한다.

방법론과 수식은 [results/METHOD.md](results/METHOD.md) 에 있다.

---

## 결론 세 줄

- **점 예측 개선은 5.3% 다. 작다.** 이 데이터는 직전 달이 다음 달의 R²=0.958 을
  설명해서 어떤 모델도 "직전 달 복사"를 유의하게 이기지 못한다
- **실질 성과는 구간 정직성이다.** 현행 80% 구간이 실제로 65.7% 만 덮었고, CQR 로
  80.1% 가 됐다
- **습관 변화 감지가 61주 → 4주.** 누적만 하는 모델은 금주를 14개월간 못 알아챈다

## 실행

```sh
PY=/opt/anaconda3/envs/pt_env/bin/python

$PY metrics.py           # 지표 단위검증
$PY mpp.py               # 모델 자체검증 (감지 지연·규칙성 역산·동결)
$PY load_aihub.py        # zip 스트림 → data/monthly.parquet  (~20분, 최초 1회)
$PY run_bench.py         # 14종 비교 → results/results.{csv,md}
$PY onboarding_sim.py    # 온디바이스 26주 시뮬레이션
$PY make_figures.py      # figure 6종 → results/fig/
$PY make_ppt.py          # → results/KB_Tune_예측모델.pptx
```

`run_bench.py --fast` 는 Chronos-2 를 건너뛴다 (모델 로드 ~5분).

### 의존성

시스템 conda 환경(`pt_env`)에 torch·pandas·pyarrow 가 이미 있어 그대로 쓴다.
추가한 것은 `lightgbm xgboost statsmodels scikit-learn chronos-forecasting tabulate python-pptx`.
**전용 venv 를 만들지 않았다** — torch 2.5GB 를 다시 받을 이유가 없다.
`backend/.venv` 와 섞이지 않는다 (여기는 `tools/` 아래다).

## 온디바이스 시뮬레이션 읽는 법

`onboarding_sim.py` 는 사용자 1명이 앱을 26주 쓰는 동안 폰 안의 모델이 어떻게
바뀌는지 재현한다. 4개 카테고리(카페·외식·술모임·미용실)에 각각 **인구 사전분포**와
**개인 실제값**을 따로 주고, 20주차에 술 모임을 끊는다.

전체 출력: [results/onboarding_sim.txt](results/onboarding_sim.txt)

### 컬럼

| 컬럼 | 의미 |
|---|---|
| 누적 | 실제 발생 누적 건수 (감쇠 없음) |
| **유효** | 감쇠 적용된 유효 표본수. 최근 관측에 가중된 값이라 누적보다 작다 |
| 예상금액 | 로그정규 사후분포의 중앙값 |
| 80% 구간 | 사후분포의 10~90 분위 |
| 추정주기 | $1/\mathbb{E}[\lambda]$ |
| 규칙성 | 간격 변동계수에서 역산한 Weibull 형태. 1=무작위, >1=주기적 |
| 7일내 | 향후 7일 내 발생 확률 (경과일 조건부) |
| 그만? | 그만둔 것 같은 정도. 규칙적이면 경과일로, 불규칙하면 빈도 급감으로 판정 |

### 무엇을 보면 되는가

**① 설치 직후 — 아무것도 모른다**
전부 공표 통계의 인구 평균이다. 카페 80% 구간이 3,203~19,979원 — 6배 폭이다.
"모른다"를 정직하게 표시한 상태다.

**② 1개월 — 금액보다 확신이 먼저 움직인다**
1주차에 카페 8,000 → 7,399원. 한 건으로 인구 통계를 버리지 않는다.
대신 구간이 먼저 좁아진다.

**③ 3개월 — 주기가 자리잡는다**
카페 3.5일(실제 3일), 외식 7.3일(실제 7일). 미용실은 관측 1~2건이라 아직 사전분포 근처.

**④ 20주차 이후 — 습관 변화**
술 모임 그만? 7% → 41%(2주 후) → 93%(6주 후). 그리고 종료가 확정되면 주기 추정이
동결된다 — 끝난 걸 아는데 "이제 16일 주기"로 갱신하는 건 의미가 없다.

**⑤ 26주 총평**

| | 설치 직후 | 26주 후 |
|---|---|---|
| 카페 예상 금액 | 8,000원 | 4,372원 (실제 4,500원) |
| 카페 80% 구간 폭 | 16,776원 | 4,755원 (**−72%**) |
| 주간 총액 σ | 65,593원 | 40,796원 (**−38%**) |

### 한계 — 미용실을 보라

미용실은 26주에 3건만 관측되어 주기 46.6일(실제 35일), 금액 41,333원(실제 28,000원)이다.
**저빈도 카테고리는 6개월로 부족하다.** 다만 80% 구간 22,377~76,349원이 실제값을
포함하므로 점추정은 틀리고 구간은 정직하다. 계층 사전분포를 두는 이유이기도 하다 —
관측이 부족하면 인구값 근처에 머무는 편이 안전하다.

## 검증 과정에서 잡힌 것들

자체검증이 없었으면 지나갔을 문제들이다. 전부 `mpp.py` 와 `metrics.py` 의
`_selfcheck()` 에 회귀 테스트로 남아 있다.

| 문제 | 증상 | 원인 |
|---|---|---|
| 홀드아웃 100% | 사용자 홀드아웃이 전원 선택됨 | 회원번호를 600 간격 추출했는데 5로 나눈 나머지를 씀. 600은 5의 배수 |
| 학습 타깃 NaN | 선형회귀·XGBoost 만 터짐 | `amount` 음수(순환불 달 4.0%)에서 `log1p` 붕괴. LightGBM 은 NaN 을 삼켜서 조용히 통과 |
| shrinkage 미작동 | WAPE 0.42 | docstring 에 "학습셋에서 고른다"고 쓰고 k=2 하드코딩 |
| 변화 판정 편향 | 습관 불변인데 두 추정이 1.9배 벌어짐 | 판정에 사후분포를 씀. 사전분포 무게가 fast 를 강하게 끌어당긴다 → 원시 관측률로 교체 |
| 규칙성이 빈도를 흔듦 | 형태를 바꾸면 평균 간격이 변함 | Weibull scale 을 $k/\lambda$ 로 둠 → $\Gamma(1+1/k)$ 보정 |
| 규칙성 과대 추정 | 카페가 1.0 대신 1.7 | 집계 건수를 $\Delta/N$ 로 균등 분할해 간격을 날조 → 분산 인위적 축소. 실제 관측 간격만 사용 |
| 종료 판정 오탐 | 카페에 "그만두셨나요?" 55% | 무기억 분포에서 긴 공백은 종료의 증거가 못 된다 → $k \ge 1.3$ 게이트 |
| 감지 악화 | 신규 습관 감지 6주 → 15주 | 주기 보정 감쇠를 fast 에도 적용 → slow 에만 적용 |
| 불규칙 습관 종료 미감지 | 금주했는데 신호 0% | 규칙성이 학습돼 게이트가 닫힘 → 불규칙 카테고리는 빈도 급감 경로로 분리 |
| 감지 지표 오설계 | 이중 추정기가 19주로 나옴 | "정확한 수렴"을 측정 — 사전분포를 이겨야 하는 문제라 감지 성능과 무관. "실제의 2배 안" 으로 교체 |

## 하지 말 것

- 랜덤 분할 금지. 시간 순만
- MAPE 를 주지표로 쓰지 말 것
- Chronos-2 를 기기에 넣으려 하지 말 것. 서버측 참조선이다
- Chronos-2 수치를 "성능 상한" 으로 쓰지 말 것 — 문맥 4개월 조건이다
- 시뮬레이션 결과를 실사용자 성능으로 쓰지 말 것
- AI Hub 원본을 커밋하지 말 것
- 결과가 현행보다 나쁘면 그대로 보고할 것. 지면 "현재 방식이 이 데이터에서는
  충분히 강하다" 가 정직한 결론이고, 그것도 발표할 수 있는 결과다

## 아직 안 된 것

- `mpp` 의 Swift 이식 — 지금 앱의 온디바이스 학습은 `learnedSpendRecords` 로
  사례를 축적하는 수준이다. `Counters`·`Tracker` 가 Swift 에 없다
- 주간 축 검증 — 합성 데이터 생성기 필요
- 카테고리별 규칙성 $k_0$ 의 실측 앵커링 — 공개 데이터에 발생 간격이 없다
- $\mathrm{CV}_\lambda$ 캘리브레이션 — 실사용자 커버리지 측정이 선행되어야 한다
