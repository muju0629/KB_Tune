## 슬라이드 1 — 사용한 데이터셋

| 항목 | 내용 |
|---|---|
| 출처 | **AI Hub 117. 금융 합성데이터** — `3.개방데이터 / 1.데이터 / 1.합성데이터` |
| 사용 파일 | `03.카드 승인매출정보.zip` (전체 12개 중) |
| 규모 | 압축 4.7GB / 해제 22.3GB · 월별 CSV 6개 (2018-07 ~ 2018-12) |
| 원본 크기 | **300만 회원 × 6개월 = 1,800만 행 × 430 컬럼** |
| 표본 | 체계추출 **5,000명** (회원번호 600 간격) → 30,000 행 |
| 1행의 의미 | 회원 1명 × 1개월 **집계** (`기준년월`, `발급회원번호`) |
| 타깃 | 당월 카드 이용금액 = `이용금액_신용_B0M + 이용금액_체크_B0M` |
| 분할 | **시간 순.** 학습 2018-11 / 테스트 2018-12, 각각 직전 4개월로 피처 |
| 타깃 분포 | 0원 26.8% · 중앙값 297,868원 · 우편향(평균 > 중앙값) |
| 디스크 사용 | **0바이트 추가** — zip 을 풀지 않고 스트림으로 필요한 18컬럼만 읽음 |

**전처리 2건 (결과에 영향)**
1. 순환불 달(원본 4.0%, 1,195행·407명)을 0원으로 클리핑 — 취소가 승인을 초과한 달
2. 전 모델에 앱의 `CLAMP_MULTIPLIER = 2.5` 동일 적용 — 한 모델만 빼면 공정하지 않음

**데이터의 결정적 성질** → `fig/6_autocorr.png`
직전 달이 다음 달의 **R² = 0.958** 을 설명한다. 건수 자기상관은 0.989.
개인 간 분산(0.760)이 개인 내 분산(0.159)의 5배 — 이 때문에 총액 WAPE 는
"고소비자를 고소비자로 맞히는 것"에 지배되고 모델을 구분하지 못한다.

## 슬라이드 3 — 우리 모델의 성능 (정직한 버전)

**① 정확도 개선은 5.3%다. 작다.**
R0 0.1370 → R6 0.1297. 그리고 변화량 기준으로는 최고가 naive 대비 **2.3%** 개선뿐이다
(`fig/3_change.png`). 위 데이터에서 직전 달이 96%를 설명하기 때문이다.

**② 진짜 성과는 구간 정직성이다** → `fig/2_coverage.png`
현재 방식의 "80% 구간"은 실제로 **65.7%만** 덮는다. CQR 적용 후 **80.1%** —
목표를 정확히 맞췄다. 앱이 화면에 표시하는 "신뢰도"가 처음으로 근거를 갖는다.

**③ σ 하드코딩을 제거했다** → `fig/5_sigma.png`
`SPEND_SIGMA = 100_000` 고정값을 일정·남은일수 기반 계산으로 대체.
고정값은 월초에 **2.4배 과소**, 월말에 **3.8배 과대**였다. iOS·백엔드 동일 수식.

**④ 습관 변화 감지** → `fig/4_detection.png`
금액과 주기를 한 모델로 다루는 계층 marked renewal process 를 온라인 학습으로 구성.
누적만 하면 금주를 **61주(14개월)** 못 알아챈다 → 이중 추정기로 **4주**, 거짓경보 0회.
켤레사전분포라 갱신이 닫힌 형태 — 폰에서 카운터만 올리면 되고 서버 전송이 없다.

**⑤ 안 써야 할 것을 데이터로 확정했다**
- Chronos-2 (1.2억 파라미터 사전학습): 계절 naive 에게 짐 (0.1365 vs 0.1327)
- XGBoost: LightGBM 과 차이가 노이즈 수준 (0.1319 vs 0.1328)
- 딥러닝: GBM 단일조차 현재 방식보다 **25.7% 나쁨** → 사용자당 표본 부족이 원인

## 한계 (슬라이드에 반드시 병기)

1. **AI Hub 데이터 자체가 합성이다.** 실사용자 소비 패턴이 아니다
2. **월 단위다.** 앱 주지표는 주간 총 지출인데 12개 zip 전부 회원×월 집계이고
   거래 단위 레코드가 없어 주간 축을 복원할 수 없다
3. **일정 단건 금액·발생 확률은 이 데이터로 평가 불가** — 거래 단건이 없어
   분위 회귀의 타깃이 존재하지 않는다
4. **R0 은 앱의 예측 모델이 아니다.** 앱에 시계열 예측은 없다 —
   `estimate.py` 는 일정 단건 추정, `budget.py` 는 남은예산÷남은주수 배분 산수다
5. **Chronos-2 는 문맥 4개월뿐**이라 이 수치를 "상한선"으로 읽으면 안 된다
6. **감지 지연은 시뮬레이션이다.** 실사용자 습관 변화로는 아직 검증되지 않았다
7. 2018년 하반기 데이터 — 현재 물가 수준과 다르다

## 발표에서 쓸 수 있는 문장 / 쓸 수 없는 문장

| ✅ 쓸 수 있다 | ❌ 쓸 수 없다 |
|---|---|
| 구간 신뢰도를 65.7% → 80.1% 로 교정했다 | 예측 정확도를 크게 개선했다 |
| σ 고정값을 상황 반응 계산으로 대체했다 | 실사용자에서 X% 개선했다 |
| 14종 비교로 무거운 모델이 불필요함을 확인했다 | 주간 예상 지출 정확도를 검증했다 |
| 습관 변화 감지를 61주 → 4주로 줄였다 (시뮬레이션) | 이 표의 Chronos 수치가 성능 상한이다 |
