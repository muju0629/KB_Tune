작성 기준: `develop` HEAD 2026-07-29. **여기 적힌 수치·기능은 전부 코드에 실재한다** —
질문 받았을 때 파일을 열어 보여줄 수 있는 것만 적었다.

시간 배분: 도입 1분 · 문제 전환 2분 · 설계 3분 · 구현·검증 3분 · 확장·마무리 1분

## 슬라이드 4 — 그래서 뒤집었습니다 (2:00~3:00) ⚡ 핵심

**차단 목록(blocklist) → 허용 목록(allowlist)**

```
❌ 지명을 지운다        → 사전에 없는 지명 하나가 그대로 나감
✅ 코드에 있는 말만 나간다 → 없는 말은 나갈 방법이 없음
```

실제 동작:

```
사용자: "제주도 3박4일 여행"
   ↓ 앱이 읽는 것: 카테고리(여행) + 구조 신호(3박)
   ↓ 나가는 검색어: "국내 3박 여행 1인 평균 경비"
   제주도는 어디에도 남지 않음
```

> 말: "제목의 낱말을 **하나도 복사하지 않습니다.** 읽는 건 유형과 숫자뿐이고,
> 검색어는 코드에 적힌 말로 새로 조립합니다."

**시각**: 위 3단 변환을 그대로. 이 슬라이드가 발표의 심장이다.

## 슬라이드 5 — 피라미드: 사용자가 정하는 AI 사용량 (3:00~4:00)

```
        ┌──────────────────────────┐
   3층  │ 웹 검색          선택     │  코드가 만든 검색어만
        ├──────────────────────────┤
   2층  │ 외부 AI(문장 생성) 선택   │  파생 금액 + 의도 라벨
        ├──────────────────────────┤
   1층  │ 기기 안 엔진      기본    │  나가는 것 0
        └──────────────────────────┘
```

**기본값이 1층입니다.** 아무 설정도 안 하면 외부 호출이 **0건**이고, 그 상태로 앱의
모든 기능이 동작합니다.

| 층 | 나가는 것 | 안 나가는 것 |
|---|---|---|
| 1층 | 없음 | — |
| 2층 | 파생 금액(가처분·남은 예산), 일정의 날짜·유형·금액, 금융 의도 | **일정 제목, 질문 원문, 이름, 나이** |
| 3층 | 코드가 조립한 검색어 한 줄 | 예산·일정·이름 (이 경로에 칸이 없음) |

> 말: "AI를 얼마나 쓸지는 사용자가 정합니다. 다만 **무엇을 지킬지는 사용자가 고를
> 일이 아니라 코드가 지킬 일**이라고 봤습니다."

## 슬라이드 7 — 숫자는 코드, 문장만 AI (4:40~5:40) ⚡ 차별점

```
요청 → [결정론 엔진] → 모든 숫자 → [AI] 문장 → [검증] → 응답
         몬테카를로 20,000회        설명만      지어낸 숫자 차단
         시드 고정 = 재현 가능
```

**AI는 금액을 만들 수 없습니다.** 엔진이 만든 숫자 목록에 없는 값을 말하면 걸러냅니다.

- 틀린 숫자가 1~2개 → 그 숫자에만 `(확인 필요)` 표시, 나머지 문장은 살림
- 3개 이상 → 답변 전체를 템플릿으로 교체
- 어느 쪽이든 **평가에서는 모델 실패로 집계** — 안전 폴백과 모델 품질을 같은 100%로 포장하지 않음

> 말: "금융 앱에서 AI가 금액을 지어내면 그건 버그가 아니라 사고입니다. 그래서 숫자를
> 만들 권한 자체를 안 줬습니다."

**시연 포인트**: 같은 질문에 화면 숫자와 대화 숫자가 일치하는 것을 보여준다.

## 슬라이드 12 — 남은 것 (8:50~9:20) ⚡ 신뢰를 버는 슬라이드

**아직 못 한 것을 먼저 말합니다.**

- 일정을 **말로** 넣는 경로는 문장이 그대로 모델에 갑니다 ("금요일에 치과 예약 넣어줘").
  무엇을 넣을지 알아내야 하기 때문입니다. **동의 화면이 이 사실을 그대로 고지하고**,
  문장을 보내기 싫으면 직접 입력 화면을 쓰면 됩니다.
- 모델 제공자의 보존·학습 이용 정책은 계약 시점에 확인해야 할 전제로 남습니다.
- KB Pay 연동은 실연동이 아니라 데모입니다. 시스템 팝업을 흉내내지 않고
  **앱 안의 연결 동의 시트**로 만들었습니다.

> 말: "다 됩니다라고 말하지 않겠습니다. 어디까지 됐고 무엇이 남았는지 아는 것이
> 금융 앱에서는 더 중요하다고 생각합니다."

> 마지막 말: "저희가 만든 건 소비 계획 앱이지만, 배운 건 **AI를 어디에 안 쓸지

## 발표 팁

- **슬라이드 3→4가 이 발표의 전부다.** 여기서 심사위원이 "아 이 팀은 다르다"고
  생각하지 않으면 나머지는 안 들린다. 시간을 여기 쓴다.
- 기능 나열을 하지 않는다. 기능은 시연이 보여준다.
- 법 조항을 읽지 말고 **"그래서 무엇을 못 하게 했는지"**를 말한다.
- 슬라이드 12(남은 것)를 빼고 싶어지겠지만 넣는다. 금융 심사에서 한계를 아는 팀이
  모르는 팀보다 신뢰받는다.
